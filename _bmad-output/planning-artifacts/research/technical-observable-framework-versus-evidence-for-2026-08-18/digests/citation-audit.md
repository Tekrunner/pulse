# Semantic citation audit

Scope: executive summary, weighted matrix, health conclusion, current implementation reality, lock-in/failure modes, and verdict. Evidence was limited to `research.md` and the pre-existing sibling digest files. Findings below are citation mismatches, unsupported wording, or claims stated more strongly than those digests permit.

1. **High — line 24, “Both can … run DuckDB-WASM over Parquet in the browser” (`[10][11][14][15]`).** `[11]` supports Observable's browser DuckDB/Parquet path, but none of the cited Evidence sources supports Evidence's browser DuckDB-WASM/Parquet path: `[14]` is the custom-component boundary and `[15]` is GitHub Pages deployment. The verified fit digest assigns the Evidence runtime half to issue `[20]` and explicitly qualifies it as a reproducible repository report rather than a maintainer architecture specification. **Correction:** add `[20]` to this sentence and say “Both have documented/supported static-build and browser-query paths”; do not imply that the combined production deployment has been proven.

2. **Medium — lines 51 and 86, “Both integrated paths currently use DuckDB-WASM 1.29.0.”** The cited sets (`[11][16][20]` at line 51; effectively `[11]`, then `[19][20]`, at line 86) do not support the exact Observable version. The digests derive Observable 1.29.0 from the Framework v1.13 release record/current manifest, neither of which has a corresponding appendix reference; `[11]` establishes DuckDB-WASM, not 1.29.0. **Correction:** add the Observable release/manifest as a source (and cite Evidence's exact manifest source), or narrow both occurrences to “Both integrated paths use DuckDB-WASM.” Scope any exact stack wording to the checked versions/snapshots.

3. **Medium — line 50, “Evidence provides … an official Playwright route” (`[12][14][16]`).** None of those references is the official Evidence E2E README from which the digest derives the Playwright claim. `[16]` is the package manifest and cannot establish the documented real-project test route. **Correction:** cite the Evidence E2E README as a distinct source, or remove “official Playwright route” and retain only the Svelte/compiler-boundary comparison supported by `[14][16]`.

4. **Medium — line 56, “the approved weights.”** Approval/provenance of the weights is not represented in any allowed digest or citation, and this audit was barred from consulting project decision documents. **Correction:** say “the stated weights” unless an in-scope decision-frame source is cited. The arithmetic conclusion that Observable remains ahead if health scores are equal is otherwise correct.

5. **Medium-high — line 78, “Repository activity therefore favors Observable slightly, not decisively.”** The verified repository data are mixed: Observable has more recent `main` activity, but its post-2024 authorship is more concentrated; Evidence has more 2026-Q1 commits/authors but no later `main` commits. The broader health digests favor Observable's *overall present support posture* only after package-maintenance, responsiveness, and strategic-direction evidence is combined. No citation appears on this load-bearing conclusion. **Correction:** “Taken together, the package-maintenance, support, repository, and strategy evidence favors Observable's present support posture slightly; repository activity alone is mixed,” with the relevant health citations.

6. **Medium — line 88, “No controlled, current performance comparison exists.”** The digests establish only that no such comparison was found in the bounded research; they cannot establish global nonexistence. **Correction:** “No controlled, current performance comparison was found in this research.”

7. **Low-medium — line 92, “Both projects are permissively licensed and forkable ….”** The claim is supported inside the exit digest (Observable ISC; Evidence MIT), but `research.md` gives it no inline citation, despite using it to frame the failure-mode strategy. **Correction:** cite the Observable repository/license and Evidence package-manifest/license sources; keep the long-lived-fork comparison explicitly framed as an engineering-cost inference.

8. **Medium — line 123, “feature development effectively stopped after 2024” (`[1][5][6]`).** `[1]` proves a commit cliff and concentration; `[5][6]` support strategic redirection and Cloud deprecation. They do not, by themselves, prove that feature development stopped. The verified release evidence supports the narrower fact that no stable major/minor feature candidate shipped after v1.13.0 on 2024-11-13. **Correction:** say “no stable feature-candidate release has shipped since November 2024, and post-2024 `main` activity is sparse,” and add `[3]` for the release timeline.

No other load-bearing citation/wording mismatch was found in the audited sections. In particular, the commit/release counts, Evidence `next` characterization, static-output paths, plain-DOM-versus-Svelte boundary, Evidence base-path defect (when kept conditional), and Evidence CLI/manifest/template coupling are supported at the stated level by the verified digests.
