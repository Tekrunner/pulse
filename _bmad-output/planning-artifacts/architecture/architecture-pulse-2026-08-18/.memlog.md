- (decision) [ADOPTED by Yann] Design paradigm: pipes-and-filters with static artifact boundaries. Binds ingestion, archive, transformation/testing, publication, site generation, and browser delivery; prevents stages from coupling through mutable shared process state or bypassing replayable artifacts. Rule: fetch -> immutable snapshot -> transform/test -> publish Parquet plus status -> static site build -> browser query/render; each stage consumes immutable/versioned artifacts and emits the next, and browser code is a terminal read-only consumer.
- (constraint) The paradigm must preserve per-source cadence, full rebuild from raw, suspect-data publication with visible marking, failure attribution by stage, and structural public/private separation.
- (decision) [ADOPTED by Yann] Workflow topology: one independently scheduled workflow per source owns acquisition, immutable snapshot, landing preparation, tests, published Parquet, and per-source status; a separate site-build/publish workflow is the sole aggregator. This binds cadence and failure isolation and prevents one global ingestion job from coupling unrelated sources.
- (decision) [ADOPTED by Yann] GitHub Actions supplies scheduling, triggering, concurrency, and runners; thin per-source workflows call shared reusable workflow structure, while repository-local commands implement the workflow steps. This prevents business/data logic from living in Actions YAML.
- (decision) [ADOPTED by Yann] dlt is the common ingestion and landing substrate for API, remote-file, and private/local-file sources. It owns source access, authentication/pagination where applicable, exact original-file archiving, source-format decoding through built-in or source-specific readers, and faithful landing Parquet; dbt-duckdb begins at landing Parquet and solely owns analytical typing, transformation, tests, disposable DuckDB materialization, and published dataset Parquet.
- (constraint) Every file-based source retains its immutable original before decoding. Each source owns a decode contract and emits landing Parquet plus observed-schema and decode-status manifests. Compatible additions may evolve and are reported; missing required fields and incompatible types are flagged; undecodable changes fail that source's decode stage without losing the raw snapshot. dlt state and schemas are implementation metadata, never the sole rebuild authority.
- (decision) [ADOPTED by Yann] Source failure semantics: a successfully decoded snapshot advances even when assertions make it suspect, and its dataset is published with visible warning status. If a snapshot is archived but cannot be decoded, retain it, emit fresh failed-stage status, keep the last successfully derived dataset available, and let unrelated source and site workflows continue. This prevents one source-format break from blocking the site without pretending the stale dataset is current.
- (decision) [ADOPTED by Yann] Source-as-vertical-slice package contract: each sources/<source-id>/ package co-locates its declaration (identity, cadence, privacy, licence, attribution), dlt ingestion/reader, decode and schema contract, source assertions, dbt staging/dataset models, and tests. Shared commands discover source packages without a central registry. Immutable snapshots, disposable landing artifacts, published dataset Parquet, and per-source status remain in separate artifact roots keyed by source id and snapshot/run identity. This binds the add-source workflow and prevents source logic from scattering across tool-owned directories.
- (decision) [ADOPTED by Yann] Privacy is enforced through separate build profiles and artifact roots with positive public inclusion. Public CI discovers only public sources, receives no private credentials or directories, propagates privacy through declared dependency lineage, and fails if a public dataset or report reaches a private source. Private builds are local, may combine public and private sources, and write only to ignored never-deployed roots. Public artifact scanning is defense in depth, not the primary boundary.
- (decision) [ADOPTED by Yann] Provenance and health use versioned application-owned Pulse manifests, not dlt state, dbt artifacts, or GitHub Actions APIs. Immutable snapshot manifests identify source, platform-independent run, acquisition time, source-data date, original files/URLs, content hashes, observed-schema hash, decoder/tool versions, licence, and attribution; landing and dataset manifests reference the originating snapshot identity. One replaceable per-source status projection reports stage outcomes, freshness, assertions, and latest usable dataset. Site builds consume only these contracts, keeping public CI and private local behavior equivalent and tools replaceable.
- (decision) [ADOPTED by Yann] Client report boundary: a report owns dataset selection, parameterized SQL, controls/reactivity, provenance copy, and routing; an application-owned dataClient wraps DuckDB-WASM and returns plain rows; a framework-neutral visual module accepts rows plus display options and returns DOM/SVG. Visuals contain no SQL, DuckDB, Parquet-path, Observable-runtime, or routing knowledge, and rendering logic is unchanged when mock rows are replaced by real query results. Visuals expose cleanup only for resources outside their DOM subtree.
- (decision) [ADOPTED by Yann] Concurrent source workflows compute independently and upload source-scoped change sets, but all default-branch mutation passes through a short final repository-writer job sharing one global concurrency group. The writer starts from the latest default branch, applies only one source change set, and atomically commits its snapshot, dataset, manifests, and status; site builds use a separate latest-wins concurrency group. This preserves parallel pipeline work while preventing stale-checkout push races, conflicting history, and partial source publication without PR or external coordinator overhead.
- (decision) [ADOPTED by Yann] Runtime policy: Python 3.13 managed by uv/uv.lock and Node 24 LTS managed by npm/package-lock are the baseline lines. Direct dependencies express compatible ranges while committed lockfiles pin the tested graph; CI uses locked/frozen installation and fails rather than rewriting locks. Dependency upgrades are explicit tested changes and never occur during scheduled ingestion. This avoids premature Python 3.14 optional-extra risk and non-LTS Node drift while preserving reproducibility.
- (decision) [ADOPTED by Yann] One repository-local Pulse CLI is the automation interface for source runs, snapshot replay, site builds, profile selection, and verification. GitHub Actions, local/private execution, and agent-authored workflows invoke the same high-level commands; they do not compose dlt, dbt, manifest, or promotion steps themselves. Lower-level stage commands may support diagnosis but are not workflow APIs. This prevents orchestration logic and tool coupling from diverging across YAML, local scripts, and agents.
- (decision) [ADOPTED by Yann] Verification boundary: every source package passes one shared offline conformance suite over committed small fixtures, proving deterministic decoding, Pulse-manifest validity, schema-drift behavior, raw-snapshot replay, and profile/privacy rules; source-specific assertions and dbt tests add domain checks. Scheduled source runs are the live integration test and distinguish upstream from code/test failures. Visuals test against plain mock rows; Playwright covers an assembled nested report, reload, DuckDB-WASM startup/query failures, and the public artifact scan. Sources cannot invent incompatible verification shapes.
- (decision) [ADOPTED by Yann] Deployment model: the default branch stores code, immutable public snapshots, published dataset Parquet, and Pulse manifests; generated site HTML/JS/WASM and copied site assets are never committed. A clean public site workflow builds one verified artifact and deploys that exact artifact through GitHub Pages without rebuilding. Browser-readable Parquet is copied beneath the site root for same-origin, repository-subpath-safe DuckDB-WASM access. This separates durable data history from generated presentation and prevents verification/deployment drift.
- (decision) The per-source workflow topology explicitly refines PRD FR-6: a source pipeline fully rebuilds its complete owned dataset slice from raw snapshots, while the whole-pipeline command rebuilds every slice. No publication path incrementally mutates a previous dataset, and no persisted shared warehouse exists.
- (constraint) Reviewer reconciliation closes the Pulse-contract protocol: `runtime/contracts/` solely owns versioned UTF-8 JSON schemas and well-known filenames; all boundaries validate them strictly and reject unsupported majors. Dataset IDs are `<source-id>/<dataset-id>`; source pipelines are `source/<source-id>`; system pipelines reserve `system/*`; catalog generation fails on all ID, table-name, and route collisions.
- (constraint) Report declarations canonically own requested privacy and compile lineage-derived resolved privacy into the report catalog. Browser dataset URLs are manifest-relative, and reports reference stable dataset IDs rather than files or DuckDB table names.
- (constraint) Pipeline state uses canonical stages and one error envelope. A missing contract-compliant artifact is failed; a published contract-compliant artifact with failed domain/freshness assertions is suspect; expired validity is stale; display precedence is failed, suspect, stale, succeeded. The newest successfully transformed publication remains usable even when suspect, while failed attempts do not replace it.
- (constraint) Cross-visual presentation is owned by `site/design/tokens.css` and `site/design/visual-language.md`; visual-contract v1 is the only report-slot major until an atomic migration or application-owned adapter is adopted. Manual private files enter only through ignored `private/inbox/<source-id>/` via the common Pulse CLI.

- (decision) [ADOPTED by Yann] Browser lifetime: the application shell owns one dataClient and DuckDB-WASM worker/connection for the loaded page session. Reports borrow it across route changes; query cancellation is request-scoped; only the shell disposes shared resources on page unload.
- (decision) [ADOPTED by Yann] Acquisition idempotence: every logical scheduled or manual observation receives one platform-independent Pulse acquisition ID that retries reuse. The writer converges identical retries, rejects conflicting content for one ID, and preserves later observations separately even when their bytes are identical.

Snapshot immutability remains invariant.
