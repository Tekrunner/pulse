# Add a Pulse report

Own the complete sequence and return control here after every dependency. Keep a durable work record at `_bmad-output/report-workflows/<report-id>.json`; resume at its first incomplete, digest-verified gate. Never ask the user to manually sequence source, dataset, and visual skills.

1. Read [references/workflow.md](references/workflow.md). Record the standing questions, indicators, context, expected reading behavior, privacy expectation, and exploration need. Discover existing snapshots and report-facing contracts by stable ID. For every source candidate record authority, coverage, granularity, stability, access method, format, licence, attribution, cadence, publication schedule, and redistribution constraints before recording the reasoned selection. Never assume a preferred provider.
2. If a suitable snapshot is missing, invoke `pulse-add-source` and pause until its immutable output verifies. If a report-facing contract is missing, invoke `pulse-add-dataset` and verify its manifest, Parquet, schema, and real rows. Record artifact paths and SHA-256 digests before resuming.
3. Once every real-data dependency verifies, create one self-contained report-level Claude Design handoff containing all questions, contracts, representative real rows, annotations, states, interaction needs, and design-foundation inputs. Claude Design owns the complete composition and every identifiable visual section. Do not derive presentation from the report template or an existing report.
4. Pause for explicit human approval. Store the human decision in a separate JSON approval artifact whose own digest is locked by the work record and whose `handoffSha256` matches the one shared handoff. Never treat freely editable inline metadata as approval. Ask before unresolved rights, cross-dataset shared state, shared-contract edits, new dependencies, design deviations, or migrations.
5. Generate design-free infrastructure from `site/workflows/add-report/template/`: declaration, parameterized queries, schemas, state/accessibility boundaries, route registration, and synthetic tests. Add versioned annotations only when contextual events are needed; when present, join them to analytical rows before visual mapping. Resolve privacy through every dataset and annotation dependency; unknown lineage is private and must fail closed.
6. Implement the approved handoff faithfully. For each visual, invoke the implementation and evidence gates of `pulse-add-visual` against its section of the shared handoff—never start a new design session. Require a declared question/schema, exact numeric-boundary proof, accessible data equivalent, responsive rendered comparison, and all declared states. Keep SQL, storage, routing, and engine lifecycle outside visuals.
7. Verify report registration, reachable-public packaging, slot-local failure isolation, safe retry, interaction/focus/viewport retention, WCAG 2.2 AA states, exact pinned values, desktop/narrow/zoom rendering, and regressions. Completion requires both numeric and fidelity evidence for every visual, not merely a green test suite.

Use `assets/report-workflow.json` as the work-record schema. Run `scripts/workflow.py status <record>` whenever resuming; any missing or changed artifact reopens its gate. Do not weaken isolation, hardcode annotation coordinates, add a chart library, hand-edit generated catalogs, duplicate data semantics, or change the review status of Stories 2.2–2.4.
